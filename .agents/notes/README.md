# Agent notes

这里保存需要跨会话接续的问题调查与决策依据。入口及推进顺序见[AI 协作方案](../README.md)。

路径使用 `<生命周期>/<主题>/YYYY-MM-DD-主题.md`，日期是首次建档日期：

- `proposed/`：待实施的提案或尚未解决的调查。
- `implemented/`：已实现且有验证依据的决定；实现路径变化时同步更新事实。
- `rejected/`：不再采用的提案，保留仍有用的原因。
- `archived/`：已经过时的历史分析或方案，保存原有背景，不作为当前实现与操作依据。

按实际需要建立目录，主题使用 `bug-fix`、`testing`、`architecture`、`simplification`、`process`。
使用 `rg --files .agents/notes/proposed` 或按关键词搜索寻找活动工作，不另建一份状态索引。

每篇至少说明：问题、已知事实与证据、建议下一步、完成条件、风险或备选方案。
第一行是中文标题，之后单列 `Status: proposed`、`Status: implemented` 或
`Status: rejected — 原因` 或 `Status: archived`，与目录一致。正文使用中文。
路径状态表示是否解决；调查中“待复现”“已拿到异常栈”等细节写在正文。

证据应包含来源提交或 dirty 状态、关键开关、命令、实际结果和产物位置。
本机 out 文件可能消失，因此异常码、文件哈希、关键错误和未验证范围要写入 note，不能只留日志路径。
假设应标为假设，通过和失败的运行分别记录；后续通过不能覆盖早先失败。

接续时先核对文件与构建身份，再执行原 note 的具体下一步。
只有完成条件满足才能移到 `implemented/`；移动时修正状态、替换提案为实际决定并修复入链。
未复现、绕开失败、减少测试范围均不足以关闭问题。
已完成的稳定事实归入对应 docs，note 保留原因、取舍及证据入口。
小型布局调整、聊天转录和原始日志无需单独建档。

从旧文档迁入时，日期沿用正文明确的记录日期；没有可靠首次日期的材料使用本次建档日期，
保留原文版本信息。提案中的目录/API 示例不表示源码已经存在。
实施验证 note 的 implemented 只确认其声明的改动与测试范围，正文保留的失败和未验证项仍然有效。
